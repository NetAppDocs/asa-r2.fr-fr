= Migrer une machine virtuelle de stockage d'un cluster ASA vers un cluster ASA r2
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
À partir d'ONTAP 9.18.1, vous pouvez migrer sans interruption une machine virtuelle de stockage (VM) de n'importe quel cluster ASA standard vers n'importe quel cluster ASA r2 afin d'adopter l'architecture simplifiée et rationalisée des systèmes ASA r2 pour les environnements exclusivement SAN.


NOTE: Vous ne pouvez pas migrer une machine virtuelle de stockage d’un ASA MetroCluster vers un cluster ASA r2. Les systèmes ASA r2 ne prennent pas en charge les configurations MetroCluster.

Les systèmes ASA r2 prennent en charge la technologie QuickAssist (QAT). Les systèmes ASA ne prennent pas en charge QAT. À partir de ONTAP 9.20.1, ONTAP réduit la latence de lecture élevée et l'utilisation du processeur qui peuvent survenir après la migration d'une machine virtuelle de stockage (VM) d'un système ASA (non-QAT) vers un système ASA r2 (QAT).

La migration des machines virtuelles de stockage entre les systèmes de stockage ASA et ASA r2 est prise en charge comme suit :

Pour obtenir la liste la plus récente des systèmes ASA et ASA r2, consultezlink:https://hwu.netapp.com/["NetApp Hardware Universe"^] .  Les systèmes ASA r2 sont répertoriés dans NetApp Hardware Universe sous le nom de «ASA série A/série C (nouveau) ».

Vous pouvez migrer une machine virtuelle de stockage vers un cluster ASA r2 uniquement à partir d’un cluster ASA. La migration à partir de tout autre type de système ONTAP vers un système ASA r2 n’est pas prise en charge.

.Avant de commencer
Tous les nœuds du cluster ASA r2 et du cluster ASA doivent exécuter ONTAP 9.18.1 ou une version ultérieure.  Les versions des correctifs ONTAP 9.18.1 sur les nœuds du cluster peuvent varier.



[[step-1-verify-the-status-of-the-asa-storage-vm]]
== Étape 1 : Vérifier l’état de la machine virtuelle de stockage ASA

Avant de migrer une VM de stockage depuis un système ASA , aucun espace de noms NVMe ni vVols ne doit être présent et chaque volume de la VM de stockage ne doit contenir qu'un seul LUN.  La migration des espaces de noms NVMe et des vVols n'est pas prise en charge.  L'architecture des systèmes ASA r2 exige que les volumes contiennent un seul LUN.

.Étapes
. Vérifiez qu'aucun espace de noms NVMe n'est présent dans la machine virtuelle de stockage :
+
[source, cli]
----
vserver nvme namespace show -vserver <storage_VM>
----
+
Si des entrées sont affichées, les objets NVMe doivent êtrelink:https://docs.netapp.com/us-en/ontap/nvme/convert-namespace-to-lun-task.html["converti"^] aux LUN ou supprimés.  Voir le `vserver nvme namespace delete` et le `vserver nvme subsystem delete` commandes dans lelink:https://docs.netapp.com/us-en/ontap/concepts/manual-pages.html["Référence des commandes ONTAP"^] pour plus d'informations.

. Vérifiez qu'aucun vVols n'est présent dans la machine virtuelle de stockage :
+
[source, cli]
----
lun show -vserver <storage_VM> -class protocol-endpoint,vvol
----
+
Si des vVols sont présents, ils doivent être copiés sur une autre machine virtuelle de stockage, puis supprimés de la machine virtuelle de stockage à migrer.  Voir le `lun copy` et `lun delete` commandes dans lelink:https://docs.netapp.com/us-en/ontap/concepts/manual-pages.html["Référence des commandes ONTAP"^] pour plus d'informations.

. Vérifiez que chaque volume de la machine virtuelle de stockage contient un seul LUN :
+
[source, cli]
----
lun show -vserver <storage_VM>
----
+
Si un volume contient plusieurs LUN, utilisez le `volume create` et `lun move` commandes pour créer un ratio volume/LUN de 1:1. Voir lelink:https://docs.netapp.com/us-en/ontap/concepts/manual-pages.html["Référence des commandes ONTAP"^] pour plus d'informations.



.Et la suite ?
Vous êtes prêt à créer une relation de pair à pair entre vos clusters ASA et ASA r2.



[[step-2-create-a-cluster-peer-relationship-between-your-asa-and-asa-r2-clusters]]
== Étape 2 : Créez une relation de pair à pair entre vos clusters ASA et ASA r2

Avant de pouvoir migrer une machine virtuelle de stockage d'un cluster ASA vers un cluster ASA r2, vous devez créer une relation de pair à pair.  Une relation d'égal à égal définit les connexions réseau qui permettent aux clusters ONTAP et aux machines virtuelles de stockage d'échanger des données en toute sécurité.

.Description de la tâche
Le cluster ASA est le cluster source à partir duquel la machine virtuelle de stockage sera migrée, et le cluster ASA r2 est le cluster de destination vers lequel la machine virtuelle de stockage sera migrée.

.Avant de commencer
Vous devez avoir créé des LIF inter-clusters sur chaque nœud des clusters appariés en utilisant l'une des méthodes suivantes.

* link:https://docs.netapp.com/us-en/ontap/peering/configure-intercluster-lifs-share-data-ports-task.html["Configurer les LIF inter-clusters sur les ports de données partagés"^]
* link:https://docs.netapp.com/us-en/ontap/peering/configure-intercluster-lifs-use-dedicated-ports-task.html["Configurez les LIF inter-clusters sur des ports de données dédiés"^]
* link:https://docs.netapp.com/us-en/ontap/peering/configure-intercluster-lifs-use-ports-own-networks-task.html["Configurer les LIF inter-clusters dans des espaces IP personnalisés"^]


.Étapes
. Sur le cluster de destination, créez une relation entre clusters avec le cluster source et générez une phrase secrète :
+
[source, cli]
----
cluster peer create -peer-addrs <source_cluster_LIF_IPs> -generate-passphrase
----
+
L'exemple suivant crée une relation d'homologue entre le cluster 1 et le cluster 2 et crée une phrase secrète générée par le système :

+
[listing]
----
cluster1::> cluster peer create -peer-addrs 10.98.191.193 -generate-passphrase
Passphrase: UCa+6lRVICXeL/gq1WrK7ShR
            Peer Cluster Name: cluster2
            Initial Allowed Vserver Peers: -
            Expiration Time: 6/7/2017 09:16:10 +5:30
            Intercluster LIF IP: 10.140.106.185
Warning: make a note of the passphrase - it cannot be displayed again.

----
. Copiez la phrase secrète générée.
. Sur le cluster source, créez une relation de peering avec le cluster de destination :
+
[source, cli]
----
cluster peer create -peer-addrs <destination_cluster_LIF_IPs>
----
. Saisissez la phrase secrète générée sur le cluster de destination.
. Vérifiez que la relation entre pairs du cluster est bien créée :
+
[source, cli]
----
cluster peer show
----
+
L'exemple suivant illustre le résultat attendu pour des clusters appariés avec succès.

+
[listing]
----
cluster1::> cluster peer show

Peer Cluster Name   Cluster Serial Number   Availability   Authentication
-----------------   ---------------------   -------------- --------------
cluster2             1-80-123456             Available      ok
----


.Résultat
Les clusters ASA et ASA r2 sont appariés et les données des machines virtuelles de stockage peuvent être transférées en toute sécurité.

.Et la suite ?
Vous êtes prêt à exécuter la vérification préalable de la migration.



[[step-3-execute-the-migration-pre-check]]
== Étape 3 : Exécuter la vérification préalable de la migration

Avant de migrer une VM de stockage d’un cluster ASA vers un cluster ASA r2, vous devez effectuer une vérification préalable de la migration et corriger tous les problèmes requis. Vous ne pouvez pas effectuer la migration tant que la vérification préalable n’a pas réussi.

.Description de la tâche
Le cluster ASA est le cluster source à partir duquel la machine virtuelle de stockage sera migrée, et le cluster ASA r2 est le cluster de destination vers lequel la machine virtuelle de stockage sera migrée.

.Étape
. Depuis votre cluster de destination, exécutez la vérification préalable de la migration :
+
[source, cli]
----
vserver migrate start -vserver <storage_VM> -source-cluster <sourcecluster> -check-only true
----
+
Si des problèmes doivent être corrigés en vue de préparer la migration, le problème et l'action corrective s'affichent. Corrigez le problème et répétez la vérification préalable jusqu'à ce qu'elle se termine avec succès.



.Et la suite ?
Vous êtes prêt à migrer votre machine virtuelle de stockage de votre cluster ASA vers un cluster ASA r2.



[[step-4-migrate-an-asa-storage-vm-to-an-asa-r2-cluster]]
== Étape 4 : Migrer une machine virtuelle de stockage ASA vers un cluster ASA r2

Une fois votre cluster ASA préparé et la relation de pair de cluster nécessaire créée avec le cluster ASA r2, vous pouvez commencer la migration de la VM de stockage.

Lors de la migration d'une machine virtuelle de stockage, il est recommandé de laisser une marge de 30 % sur le processeur, tant sur le cluster ASA que sur le cluster ASA r2, afin de permettre l'exécution de la charge de travail du processeur.

.Description de la tâche
* Après la migration de la machine virtuelle de stockage, les E/S client basculent en toute transparence vers le cluster de destination sans interruption, et la machine virtuelle de stockage sur le cluster ASA r2 est automatiquement supprimée. Le basculement automatique et la suppression automatique de la machine virtuelle de stockage sont activés par défaut. Vous pouvez éventuellement désactiver l’une ou l’autre de ces options, ou les deux, et les exécuter manuellement.
* Le cluster ASA est le cluster source à partir duquel la machine virtuelle de stockage sera migrée, et le cluster ASA r2 est le cluster de destination vers lequel la machine virtuelle de stockage sera migrée.


.Avant de commencer
* Le cluster ASA r2 doit disposer d'un espace libre suffisant pour accueillir la machine virtuelle de stockage migrée.
* Si la machine virtuelle de stockage ASA contient des volumes chiffrés, le gestionnaire de clés intégré ou le gestionnaire de clés externe du système ASA r2 doit être configuré au niveau du cluster.
* Les opérations suivantes ne peuvent pas être exécutées sur le cluster ASA source :
+
** Opérations de basculement
** WAFLIRON
** Empreinte digitale
** Déplacement de volume, réhébergement, clonage, création, conversion ou analyse




.Étapes
. Depuis le cluster de destination, démarrez la migration de la machine virtuelle de stockage :
+
[source, cli]
----
vserver migrate start -vserver <storage_VM_name> -source-cluster <source_cluster>
----
+
Pour désactiver la bascule automatique, utilisez le `-auto-cutover false` paramètre. Pour désactiver la suppression automatique de la machine virtuelle de stockage source, utilisez le `-auto-source-cleanup false` paramètre.

. Surveillez l'état de la migration
+
[source, cli]
----
vserver migrate show -vserver <storage_VM_name>
----
+
Si vous devez suspendre ou annuler la migration avant le début du basculement automatique, utilisez la `vserver migrate pause` et le `vserver migrate abort` commandes.  Vous devez suspendre la migration avant de l'annuler.  Vous ne pouvez pas annuler la migration une fois la transition commencée.

+
Si la bascule automatique est activée, une fois la migration terminée, le *status* s’affiche comme *migration-complete*. Si la bascule automatique est désactivée, le *status* s’affiche comme *Ready for source cleanup*.



.Résultat
La machine virtuelle de stockage est migrée du cluster ASA vers le cluster ASA r2.  Le nom et l'UUID de la machine virtuelle de stockage, le nom de l'interface logique de données, l'adresse IP et les noms des objets, tels que le nom du volume, restent inchangés.  L'UUID des objets migrés dans la machine virtuelle de stockage est mis à jour.

.Et la suite ?
Si vous avez désactivé le basculement automatique et la suppression automatique de la machine virtuelle de stockage, effectuez le basculement et le nettoyage post-migration pour basculer manuellement vos clients ASA vers votre cluster de destination et supprimer la machine virtuelle de stockage du cluster ASA.



[[step-5-post-migration-cutover-and-cleanup]]
== Étape 5 : Basculement et nettoyage post-migration

Lors d'une migration de machine virtuelle de stockage entre clusters, les E/S client sont transférées vers le cluster de destination et la machine virtuelle de stockage du cluster source est automatiquement supprimée. Si vous choisissez de désactiver le basculement automatique et la suppression de la machine virtuelle de stockage source pendant la migration, vous devrez effectuer ces étapes manuellement une fois que l'état de la migration aura atteint *Ready for source cleanup*.



[[manually-cut-over-clients-after-a-storage-vm-migration]]
=== Basculer manuellement les clients après une migration de machine virtuelle de stockage

Si vous désactivez le basculement automatique du client lors de la migration inter-cluster d'une machine virtuelle de stockage, une fois la relation de migration prête pour le basculement, effectuez ce dernier manuellement afin que la machine virtuelle de stockage de destination puisse fournir des données aux clients.

.Description de la tâche
Effectuez cette tâche à partir du cluster de destination.

.Étapes
. Exécutez manuellement la bascule client :
+
[source, cli]
----
vserver migrate cutover -vserver <storage_VM_name>
----
. Vérifiez que l'opération de basculement est terminée :
+
[source, cli]
----
vserver migrate show
----


.Résultat
Les données sont fournies à vos clients depuis la machine virtuelle de stockage de votre cluster de destination.

.Et la suite ?
Vous êtes maintenant prêt à retirer la machine virtuelle de stockage du cluster source.



[[manually-remove-a-storage-vm-after-migration]]
=== Supprimer manuellement une machine virtuelle de stockage après la migration

Si vous désactivez le nettoyage automatique de la source lors d'une migration de machine virtuelle de stockage entre clusters, une fois la migration terminée, supprimez la machine virtuelle de stockage du cluster source pour libérer l'espace de stockage.

.Avant de commencer
Vos clients doivent fournir des données à partir du cluster de destination.

.Étapes
. À partir du cluster source, vérifiez que l'état de la machine virtuelle de stockage source est *Ready for source cleanup* :
+
[source, cli]
----
vserver migrate show
----
. Supprimer la machine virtuelle de stockage source :
+
[source, cli]
----
vserver migrate source-cleanup -vserver <storage_VM_name>
----


.Résultat
La machine virtuelle de stockage de votre cluster source a été supprimée.
